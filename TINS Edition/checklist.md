# Project Setup and Test Checklist

This checklist guides you through setting up the "Gemini Fullstack LangGraph Quickstart" project from scratch and testing its file-reading capability with a specific query.

## I. Prerequisites

1.  [ ] **Git:** Ensure Git is installed on your system. ([https://git-scm.com/downloads](https://git-scm.com/downloads))
2.  [ ] **Node.js and npm:** Install Node.js (which includes npm), version 18.x or later recommended. ([https://nodejs.org/](https://nodejs.org/)) (The project uses Vite, which typically requires Node.js 18+ or 20+). The original README mentions Node.js, `frontend/Dockerfile` uses `node:20-alpine`.
3.  [ ] **Python:** Install Python, version 3.8 or later (Python 3.11 is used in `Dockerfile`). ([https://www.python.org/downloads/](https://www.python.org/downloads/))
4.  [ ] **GEMINI_API_KEY:** Obtain a Google Gemini API key. ([https://ai.google.dev/gemini-api/docs/api-key](https://ai.google.dev/gemini-api/docs/api-key))

## II. Project Cloning and Initial Setup

1.  [ ] **Clone the Repository:**
    ```bash
    git clone <repository_url> # Replace <repository_url> with the actual URL
    cd <repository_directory_name> # Replace with the directory name created by git clone
    ```
2.  [ ] **Backend - Set API Key:**
    *   Navigate to the `backend/` directory:
        ```bash
        cd backend
        ```
    *   Create a `.env` file by copying `.env.example`:
        ```bash
        cp .env.example .env
        ```
    *   Open the newly created `.env` file in a text editor.
    *   Add your Google Gemini API key:
        ```
        GEMINI_API_KEY="YOUR_ACTUAL_API_KEY"
        ```
    *   Save and close the `.env` file.
    *   Return to the project root directory:
        ```bash
        cd ..
        ```

## III. Install Dependencies

1.  [ ] **Backend Dependencies:**
    *   Navigate to the `backend/` directory:
        ```bash
        cd backend
        ```
    *   Install Python dependencies:
        ```bash
        pip install .
        ```
    *   Return to the project root directory:
        ```bash
        cd ..
        ```
2.  [ ] **Frontend Dependencies:**
    *   Navigate to the `frontend/` directory:
        ```bash
        cd frontend
        ```
    *   Install Node.js dependencies:
        ```bash
        npm install
        ```
    *   Return to the project root directory:
        ```bash
        cd ..
        ```

## IV. Prepare Test Data File

The agent's `web_research` node has been modified to read local files. The paths to these files are generated by an LLM based on your input query.

1.  [ ] **Create a Directory for Test Data (Recommended):**
    *   In the `backend/` directory, create a new folder named `test_data`.
        ```bash
        mkdir backend/test_data
        ```
    This ensures paths are relative to the backend's execution context.

2.  [ ] **Create the Test File:**
    *   Inside `backend/test_data/`, create a new text file named `protagonist_info.txt`.

3.  [ ] **Add Content to Test File:**
    *   Open `backend/test_data/protagonist_info.txt` and add the following content:
        ```text
        The protagonist of our story is Alex.
        Alex is known for always saying: "Time to make some digital magic!"
        This phrase is iconic and repeated in crucial moments.
        ```
    *   Save and close the file.

## V. Run the Application (Development Mode)

1.  [ ] **Start Both Servers:**
    *   From the **project root directory**, run:
        ```bash
        make dev
        ```
    *   This command will start:
        *   The backend server (typically on `http://127.0.0.1:2024`).
        *   The frontend development server (typically on `http://localhost:5173`).
    *   Wait for both servers to indicate they are running successfully. The backend might open a LangGraph UI page in your browser automatically – you can ignore this for this test.

2.  [ ] **Access the Application:**
    *   Open your web browser and navigate to the frontend URL: `http://localhost:5173` (or `http://localhost:5173/app` if specified by dev server output).

## VI. Test the Query

1.  [ ] **Initial UI:** You should see the "Welcome" screen.

2.  [ ] **Formulate the Input Query:**
    *   In the text input area ("Describe the information or rules you are looking for..."), type a query that will guide the agent to the test file. For example:
        ```
        Please research the file located at 'test_data/protagonist_info.txt' and tell me: what's the protagonist's iconic phrase?
        ```
    *   **Explanation:**
        *   The agent's `generate_query` node will process this natural language query.
        *   The goal is for this node to extract `test_data/protagonist_info.txt` as a "search query" (which is actually a file path for the `web_research` node).
        *   The path `test_data/protagonist_info.txt` is relative to the `backend/` directory, where the `langgraph dev` server runs.

3.  [ ] **Set Effort and Model (Optional for this test, but good practice):**
    *   Select "Effort: Low" (this might help in making the agent focus on fewer, more direct "search queries"/file paths initially).
    *   Leave the "Model" as the default or select one.

4.  [ ] **Submit the Query:**
    *   Click the "Search" button (or press Enter).

## VII. Observe and Verify

1.  [ ] **Activity Timeline:**
    *   Observe the "Research" activity timeline that appears.
    *   You should see steps like:
        *   "Generating Search Queries"
        *   "Web Research" (This step should ideally show that it's attempting to process `test_data/protagonist_info.txt`)
        *   "Reflection"
        *   "Finalizing Answer"

2.  [ ] **Final Answer:**
    *   Once the agent completes, an AI message should appear with the answer.
    *   **Expected Outcome:** The answer should be something like: "The protagonist's iconic phrase is 'Time to make some digital magic!'" or similar, based on the content of `protagonist_info.txt`.

3.  [ ] **Source Indication (Implicit):**
    *   While the UI might not explicitly show "Cited from: test_data/protagonist_info.txt", the agent's answer is derived from this file. The `sources_gathered` in the backend state would contain this information.

## VIII. Troubleshooting (If it doesn't work as expected)

1.  [ ] **Check Backend Logs:** The terminal where `make dev` (or `langgraph dev`) is running will show logs from the backend. Look for:
    *   Errors related to `GEMINI_API_KEY`.
    *   The "search queries" (file paths) generated by the `generate_query` node. Is `test_data/protagonist_info.txt` among them?
    *   Any "File not found" errors from the `read_project_file` function if the path was incorrect or the file was misplaced.
    *   LLM errors during reflection or answer finalization.
2.  [ ] **File Path Issues:**
    *   Ensure `protagonist_info.txt` is correctly placed in `backend/test_data/`.
    *   Try using an absolute path in your UI query if relative paths cause issues (though relative to `backend/` should work).
3.  [ ] **Query Formulation:** If the agent doesn't generate the correct file path, try rephrasing your input query in step VI.2 to be more direct about which file to read. Example: "Read 'test_data/protagonist_info.txt'. What is the iconic phrase mentioned in it?"
4.  [ ] **Effort Level:** If "Low" effort doesn't pick up the file, try "Medium". The `generate_query` LLM call might sometimes miss the file path if it's generating only one query and focuses on the question part.

This checklist should help users set up and test the application's core file-reading functionality.
